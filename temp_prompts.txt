Prompt A - Make scheduled Craigslist runs persist listings
------------------------------------------------------------
Fix the end-to-end Craigslist ingestion path in this repository. A scheduled
run currently calls collector.run(query=""), and CraigslistCollector.save()
only keeps an in-memory seen-ID set; valid listings therefore do not appear in
database/listings.db or the dashboard. Trace the existing BaseCollector,
SchedulerService, ListingRepository, event bus, and pipeline stages. Choose
one coherent persistence path that matches the existing architecture. Ensure
valid listings are persisted, repeated source/external_id pairs are
deduplicated, invalid listings are skipped, and collector failures still
produce scheduler metrics. Use an isolated SQLite database in tests and never
call the live marketplace from tests. Add focused regression tests, then run
the focused tests, Ruff, and the full test suite.

Prompt B - Wire collector configuration into scheduler execution
------------------------------------------------------------------
Complete the collector configuration flow. Settings already define
COLLECTOR_CONFIGS with queries, locations, pagination_limit, request_timeout,
and rate_limit_per_minute, but SchedulerService currently ignores those
values and invokes each collector with an empty query. Pass the configured
queries and locations into collector execution while preserving the existing
ENABLED_COLLECTORS behavior and sensible defaults. Define what happens when a
collector has no configured queries, validate malformed configuration, and do
not expose credentials in logs or API responses. Add tests proving configured
queries and locations reach the collector, defaults remain backward
compatible, and secrets are not serialized. Update .env.example and README.md
with a working JSON configuration example.

Prompt C - Make one-time and continuous tracking observable
-------------------------------------------------------------
Improve scheduler observability without changing its public CLI names. Ensure
`uv run maie scheduler run craigslist` reports the number of discovered,
persisted, skipped, and failed listings. Ensure `uv run maie scheduler start`
starts inside a running asyncio event loop, remains alive until Ctrl+C, and
records metrics that `uv run maie scheduler status` can display while the
process is running. Add focused CLI and scheduler tests for startup, graceful
shutdown, successful execution, and failed execution. Do not start a live
network service in tests.
